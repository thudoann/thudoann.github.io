Le CI/CD expliqué simplement

L’idée : plusieurs personnes modifient le même code. Le CI/CD est une chaîne de montage automatique qui vérifie chaque modification avant qu’elle n’atteigne les utilisateurs.

  1. Commit. Un développeur enregistre une modification et la envoie dans le code partagé (par exemple sur GitHub).
  2. CI (intégration continue). Un robot construit immédiatement le projet et lance les tests. Si quelque chose casse, on le sait en quelques minutes, quand la modification est encore petite et facile à corriger.
  3. CD (livraison continue). Si toutes les vérifications passent, la nouvelle version est empaquetée et prête à être publiée à tout moment. Une personne choisit le moment de la mise en ligne.
  4. CD (déploiement continu). Même principe, mais le robot envoie aussi automatiquement chaque modification validée aux utilisateurs.

Le pipeline : ces étapes, dans l’ordre, forment un pipeline : code, puis construction, tests, empaquetage et déploiement. Les vérifications rapides sont faites en premier, pour arrêter tôt une modification défectueuse.

Où il se trouve : sur GitHub, les étapes sont écrites dans un fichier YAML placé dans .github/workflows/. Ce fichier indique quoi exécuter et quand, par exemple à chaque envoi de code.

Pourquoi c’est utile : beaucoup de petites livraisons testées sont plus sûres qu’une grande livraison que personne n’a vraiment testée.
