    ⚖️ Can you trust the LLM judge?

    An LLM-as-a-judge is an AI that grades another AI's answers. It's fast and cheap, but it can be wrong. Before trusting it, teams calibrate it: humans grade a sample, then they check how often the judge agrees with them.

    Your task: you're the human expert. For each answer, decide Good or Bad using the knowledge base. Then reveal what the judge said.
    Knowledge base: refunds within 30 days (unused items only) · ships to EU, UK, Canada (not Australia/US) · delivery 3–5 business days, no express · support help@nimbus.shop, Mon–Fri 9:00–18:00 · Premium €9/month · the bot must be polite.
    Judge's rubric: "Is the answer faithful to the knowledge base? Answer GOOD or BAD."

    🐍 What the lab does, in real Python

    This is the same eval loop you just ran, written with the Anthropic Python SDK. Swap in any LLM provider.
    # run_evals.py
import json, sys
from anthropic import Anthropic

client = Anthropic()  # reads ANTHROPIC_API_KEY from the environment
KB = open("knowledge_base.txt").read()
SYSTEM = f"""You are Nimbus Shop's support assistant.
Answer ONLY using the facts below. If the answer isn't there, say you don't know.
Politely refuse off-topic requests. Never give discount codes.
FACTS:
{KB}"""

# 1) DATASET (golden test cases)
dataset = json.load(open("dataset.json"))  # [{"question":..., "type":"contains", "value":...}, ...]

def ask_bot(question):                       # 2) RUN
    r = client.messages.create(model="claude-haiku-4-5", max_tokens=300,
                               system=SYSTEM, messages=[{"role": "user", "content": question}])
    return r.content[0].text

def check_contains(answer, case):            # 3a) CODE GRADER
    hit = case["value"].lower() in answer.lower()
    return hit if case["type"] == "contains" else not hit

def judge_faithful(answer):                  # 3b) LLM-AS-A-JUDGE
    prompt = f"""Knowledge base:\n{KB}\n\nAnswer to grade:\n{answer}\n
Does the answer contain ANY claim not supported by the knowledge base?
Think step by step, then end with exactly GOOD or BAD."""
    r = client.messages.create(model="claude-sonnet-4-5", max_tokens=400,
                               messages=[{"role": "user", "content": prompt}])
    return r.content[0].text.strip().endswith("GOOD")

passed = 0
for case in dataset:
    answer = ask_bot(case["question"])
    ok = check_contains(answer, case) and judge_faithful(answer)
    passed += ok
    print(("✅" if ok else "❌"), case["question"], "→", answer[:80])

score = passed / len(dataset)
print(f"\nScore: {score:.0%}")
sys.exit(0 if score >= 0.9 else 1)          # 4) QUALITY GATE: non-zero exit fails CI

    ⚙️ Plug it into GitHub Actions

    # .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  test-and-eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - name: Unit tests
        run: pytest
      - name: AI evals (quality gate)
        run: python run_evals.py
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    Now every prompt or model change is automatically graded. If quality drops below 90%, the pipeline goes red and nothing is deployed.
