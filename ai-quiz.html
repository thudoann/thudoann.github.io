CI/CD explained in plain words

The idea: software is built by many people changing the same code. CI/CD is an automatic assembly line that checks every change before it reaches users.

  1. Commit. A developer saves a change and pushes it to the shared code (for example on GitHub).
  2. CI (Continuous Integration). A robot immediately builds the project and runs the tests. If something breaks, you know within minutes, while the change is still small and easy to fix.
  3. CD (Continuous Delivery). If all checks pass, the new version is packaged and kept ready to ship at any time. A person chooses when to release it.
  4. CD (Continuous Deployment). Same idea, but the robot also sends every passing change to users automatically.

The pipeline: these steps, in order, are called a pipeline: code, then build, then test, then package, then deploy. Quick checks run first, so a broken change stops early.

Where it lives: on GitHub, the steps are written in a YAML file inside .github/workflows/. The file says what to run and when, for example on every push.

Why it matters: many small, tested releases are safer than one big release that nobody has fully tested.
